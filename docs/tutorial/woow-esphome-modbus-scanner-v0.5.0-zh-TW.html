完整實作指南

用 ESPHome 找出 RS-485 上的 Modbus 站號

本文件說明 Home Assistant 自訂整合 Woow ESPHome Modbus Scanner 0.5.0.dev3 與廠牌中立的 ESPHome 元件 modbus_scanner：如何把任何 ESPHome 節點變成掃描 Gateway、登錄到 HA、用 Device Profile 限制與解讀讀取、在掃描期間安全地暫停其他輪詢，以及如何解讀結果。

所有章節均顯示；停用 JavaScript 也能閱讀全部內容。

列印版本：Woow ESPHome Modbus Scanner 0.5.0.dev3 繁體中文完整教學。

1. 範圍、目的與安全

先確認：掃描只送出唯讀的 FC03／FC04 讀取；韌體拒絕所有寫入功能碼。但它仍會在 RS-485 上產生流量，並在掃描期間暫停你選定的輪詢元件。任何啟用中的 Home Assistant 使用者都能對任一已登錄 Bus 的 1–247 站號產生唯讀流量（在所選 Device Profile 的範圍內），並看到 Responder 證據；請管控 HA 帳號。

適合做

  • 找出一條 RS-485 Bus 上哪些站號會回應。
  • 用 Device Profile 讀出並解碼已知設備的暫存器。
  • 在不重刷韌體的情況下支援新的設備類別。
  • 以模擬 provider 開發儀表板、自動化與 API 用戶端。

不會做

  • 不寫暫存器、不變更站號、不重啟節點。
  • 不保證找到所有節點，也不證明一個站號只對應一台設備。
  • 不讀取 FC01／FC02／FC43 等其他功能碼。
  • 不重跑中斷的掃描。

範圍掃描必須帶字面布林值 safety_confirmed: true；超過 32 個站號（Large Range）還要 large_range_confirmed: true，因為時間與流量都會明顯增加。

2. 架構與生命週期

Gateway 是已登錄、執行 modbus_scanner 的 ESPHome 節點，剛好服務一條 Bus：唯一一個 modbus_scanner 項目指定的 Modbus hub 與其序列參數。一台 Gateway 一條 Bus；第二條 RS-485 請用另一台節點。Scan 是在一條 Bus 上對一段站號依序送出 Probe。HA 端的 coordinator 是信任邊界：驗證請求、產生 UUID、保證每台 Gateway 一次一個 Scan、統計、歷史與公開 JSON。provider 則負責傳輸：mock 為模擬；esphome 依每個 Gateway 的 Bridge Protocol 版本，轉給 Bridge Protocol v2 adapter 或已棄用的 Bridge Protocol v1 adapter。

一次 Scan 的流程

  1. start_scan 或 test_address 先套用 Device Profile 與 Gateway 的預設值，再以兩者限制的交集驗證，立即回傳 canonical UUID scan_id。
  2. adapter 連到 Gateway，確認 MAC 與 Bridge Protocol v2 簽章，讀取它唯一的 Bus 與 Pausable Poller 表（回報超過一條 Bus 的 Gateway 會被拒絕），並重新驗證暫停選擇。
  3. 第一個 Probe 開始 Scan Lease；每個 Probe 的結果以 request id 對應，逐筆交給 coordinator 再驗證。
  4. 結束（完成、取消或錯誤）時 HA 釋放 lease 並中斷連線；終態寫入 HA storage 歷史，最多 20 筆。
設計決策記錄在 ADR 0005（廠牌中立元件與 Device Profile）、ADR 0006（Pausable Poller 探索與選擇）、ADR 0007（Scan Lease）與 ADR 0011（一台 Gateway 一條 Bus）。

3. Modbus 位址與發現限制

  • Modbus Serial Line 的個別站號為 1–247；位址 0 是 broadcast，不會有回覆，因此不能掃描。
  • Modbus 沒有能列出所有設備的通用 discovery。本工具以讀取暫存器作為探測：FC03（保持暫存器）或 FC04（輸入暫存器），每次 1–4 個。
  • CRC 有效的 Modbus exception（例如 code 2 Illegal Data Address）表示該站號有 Responder，只是不接受該暫存器。
  • 重複站號、終端電阻、偏壓或雜訊會讓回覆重疊或 framing 錯誤，只能標為 possible_collision。
  • timeout 可能來自離線、暫存器不支援、鮑率／同位元不符、線路或忙碌；它不證明位址空閒。

最壞耗時估算為 站號數 × (retries + 1) × (timeout_ms + attempt_overhead_ms) + (站號數 − 1) × inter_request_delay_ms；attempt_overhead_ms 由 list_gateways 的 limits 回報（Bridge Protocol v2 為 300 ms）。timeout_ms 由 Gateway 逐個 Probe 套用：送出探測封包時暫時把 hub 的 send_wait_time 設成此值，結束時還原 YAML 的設定。

4. ESPHome 韌體：加入 modbus_scanner

需要 ESPHome 2026.9.0 或更新版本；較舊版本在設定驗證時就會失敗。保留現有的 uart、modbus 與 modbus_controller，再加入 external component 與一個指定 hub 的 modbus_scanner 項目。

esphome:
  name: my-modbus-node
  min_version: 2026.9.0

api:
  encryption:
    key: !secret api_encryption_key

external_components:
  - source:
      type: git
      url: https://github.com/WOOWTECH/Woow_ha_esphome_modbus_scanner
      path: firmware/components
    components: [modbus_scanner]

uart:
  id: rs485_uart
  tx_pin: GPIO17
  rx_pin: GPIO16
  baud_rate: 9600

modbus:
  id: rs485
  uart_id: rs485_uart

modbus_controller:
  - id: meter
    modbus_id: rs485
    address: 1
    update_interval: 10s

modbus_scanner:
  - modbus_id: rs485
modbus_scanner 在節點上建立的項目
項目名稱用途
API 動作modbus_scanner_v2_probe對一條 Bus 的一個站號做一次唯讀讀取；不需要 api: custom_services。
API 動作modbus_scanner_v2_release結束一個 Scan 的 Scan Lease。
文字感測器Modbus Scanner v2 InfoBridge Protocol 版本、那條 Bus 的名稱、序列參數與 Pausable Poller 表。

文字感測器Modbus Scanner v2 LeaseScan Lease 開始、結束與原因。

自動找出 Pausable Poller

編譯時，元件會走訪整份已驗證的設定：凡是綁在同一 hub（modbus_id）且產生的類別繼承 PollingComponent 的元件（例如每個 modbus_controller），都依 YAML 順序得到固定索引，連同名稱與站號列入那條 Bus 的表。不需要手寫清單；新增輪詢元件要重新編譯才會出現。

一台 Gateway 一條 Bus

一個節點只能有一個 modbus_scanner 項目。第二個項目會在設定驗證時失敗，訊息為 A node supports only one modbus_scanner; scan a second RS-485 line with another node。有兩條 RS-485 線的節點只能掃其中一條；第二條 RS-485 請用另一台節點。Bus 可用 bus: 命名（1–32 個 0-9 A-Z a-z _ - 字元，預設為 hub id），HA 會在每筆結果旁顯示它與序列參數。

modbus_scanner:
  - modbus_id: rs485
    bus: line_a   # 選用；預設為 hub id
協定契約：HA 與韌體之間的 Bridge Protocol v2 定義在 custom_components/woow_esphome_modbus_scanner/modbus_scan/bridge_v2/contract.json。v2 只能向後相容地增加；改變或移除既有欄位需要 Bridge Protocol 版本 3。

5. 安裝整合與登錄 Gateway

HACS 自訂儲存庫

  1. HACS → Integrations → 右上選單 → Custom repositories。
  2. 填入 https://github.com/WOOWTECH/Woow_ha_esphome_modbus_scanner，類別選 Integration。
  3. 下載 Woow ESPHome Modbus Scanner，重新啟動 Home Assistant。

手動安裝則把 custom_components/woow_esphome_modbus_scanner/ 整個複製到 HA 設定目錄的同名路徑後重新啟動。

登錄 Gateway

設定 → 裝置與服務 → 新增整合。本整合只有一個設定項目，選單提供：

  1. 從 ESPHome 裝置新增 Gateway（建議）：列出 HA ESPHome 整合中已知 MAC 的節點，沿用其主機、連接埠與 API 金鑰，經 API 驗證 MAC 與 Bridge Protocol v2 簽章後才儲存；過程不送任何 Modbus 封包。
  2. 手動新增 Gateway（進階）：輸入主機、MAC 與 API 金鑰，檢查相同；可選 Bridge Protocol v2 或 Bridge Protocol v1。
  3. 目前只用模擬 Gateway：之後再從重新設定加入實體 Gateway。

重新設定可新增、更新（取得新的主機或金鑰）或移除 Gateway，數量不限；重新認證一次驗證一個 Gateway。已儲存的金鑰不會再顯示。

Modbus Scanner 側邊欄

  1. 左側選 Modbus Scanner（雷達圖示），路徑 /woow-esphome-modbus-scanner；所有 HA 使用者都看得到。更新後請強制重新整理。
  2. 選 Gateway；掃描的是它唯一的 Bus，結果來源列會顯示 Bus 名稱與鮑率、同位元、停止位元。
  3. 選 Device Profile；表單預設值與上下限隨之改變。
  4. 按檢查 Gateway，Pausable Poller 卡片列出各輪詢元件；勾選要暫停者（預設全選，依 Bus 儲存）。
  5. 勾選盡力而為警告（超過 32 個站號另需確認），按 Start scan 或 Test address。

最小驗證

開發者工具 → 動作，執行 woow_esphome_modbus_scanner.list_gateways 並要求回應，應看到模擬 Gateway 與你登錄的 esphome: Gateway。

7. Device Profile

Device Profile 描述一類現場設備可讀的暫存器、預設值與限制。內建的 Generic Device Profile（generic）允許 FC03／FC04 的任何暫存器，不能刪除。其他 profile 是 schema_version 1 的 JSON 文件，存於 HA storage，會納入 HA 備份；匯入相同 id 會取代舊版。無效文件會逐欄列出錯誤並拒絕。

Device Profile 文件的鍵
鍵必要內容
schema_version是1
id是1–64 個小寫字母、數字、- 或 _，以字母或數字開頭；generic 保留。
name、vendor、model是非空文字，最多 64 字元。
version是非空文字，最多 32 字元。
function_codes是[3]、[4] 或 [3, 4]；寫入功能碼一律拒絕。
defaults否slave_start 與 slave_end（須同時提供）、function_code、register、count（1–4）、timeout_ms（100–2000）、inter_request_delay_ms、retries。
allowed_registers否最多 1024 個位址；有設定時只能讀這些，預設暫存器與欄位也必須在內。
fields否最多 256 個 {register, name, unit, scale, data_type}；data_type 為 u16（預設）或 s16，scale 為有限非零數字。
{"schema_version": 1, "id": "my-meter", "name": "My meter", "vendor": "Acme", "model": "M1", "version": "1",
 "function_codes": [4],
 "defaults": {"slave_start": 1, "slave_end": 10, "function_code": 4, "register": 0, "count": 2, "timeout_ms": 500},
 "fields": [{"register": 0, "name": "Voltage", "unit": "V", "scale": 0.1},
            {"register": 1, "name": "Current", "unit": "A", "scale": 0.01, "data_type": "s16"}]}

結果中，Probe 區塊內每個有定義欄位的暫存器都會在原始值旁多一筆 decoded（register、name、unit、value）；s16 會做符號延伸，scale 以精確小數計算。專案附了一份完整的範例 profile：examples/device_profiles/guanjie-ind17.json（有暫存器允許清單與具名欄位的 FC03 對照表），可直接在側邊欄匯入。

刪除規則：內建 Generic 不能刪；執行中 Scan 正在使用的 profile 要等該 Scan 結束；已完成的結果保留當時的 profile 名稱。若瀏覽器記住的 profile 已不存在，側邊欄會改回 Generic 並提示。

8. Pausable Poller 與 Scan Lease

同一條 Bus 上的其他輪詢元件若在掃描時繼續送封包，會與 Probe 交錯，造成 timeout 或錯誤歸屬。因此 Scan 會暫停你選定的 Pausable Poller。選擇方式：用 set_pausable_pollers（或側邊欄勾選清單）儲存（以 Bus 為 key），或在單次 Scan 傳入 pause_pollers。每次檢查與開始 Scan 時，都會以韌體回報的表重新驗證；韌體已沒有的元件會被移除並列在 removed_pollers，絕不送出。

由 Gateway 持有的 Scan Lease

  1. Scan 的第一個 Probe 開始 lease：選定元件停止，hub 中這些站號排隊的封包被清除，然後才送出探測封包。
  2. 同一 Scan 的每個 Probe 都會續約。
  3. Scan 完成、取消或失敗時，HA 送出釋放動作結束 lease。
  4. 若 HA 或連線消失，Gateway 在 5 秒沒有 Probe 後自行結束；無論如何在開始後 10 分鐘結束（更長的 Scan 之後不再暫停）。另一個 Scan 的 Probe 會取代（supersede）目前的 lease。
  5. 每一種結束方式，Gateway 都會自行恢復被暫停的元件。
兩個必須預期的副作用：清除暫停元件的佇列時，也會丟掉它待送的寫入（例如掃描前剛從 HA 調整的設定值），所以掃描期間請勿操作暫停中的設備；lease 結束後，恢復的元件第一次取得新讀值，最多可能要等它的一個 update_interval，在此之前其 HA 實體顯示的是舊值。
Scan 狀態中的 lease 欄位
欄位值意義
lease_statusnone、active、ended、unconfirmedunconfirmed 表示連線中斷或釋放未獲回應，改由 Gateway 的 5 秒閒置到期恢復。
lease_end_reasonreleased、idle、hard_limit、supersededlease 如何結束。
paused_pollers清單本次暫停的元件（索引、名稱、站號）。
removed_pollers清單已儲存但韌體不再有的元件。

9. UI 與自動化實作

在開發者工具 → 動作切到 YAML 貼上以下內容；有回應的動作要勾選回應，腳本與自動化用 response_variable 保存。

Lab A：列出並檢查 Gateway

- action: woow_esphome_modbus_scanner.list_gateways
  response_variable: gateways
- action: woow_esphome_modbus_scanner.check_gateway
  data:
    gateway_id: esphome:aabbccddeeff
  response_variable: checked

checked.buses 列出那條 Bus（固定一筆）的名稱與序列參數，輪詢元件清單列出索引、名稱、站號與是否暫停。

Lab B：儲存暫停選擇

action: woow_esphome_modbus_scanner.set_pausable_pollers
data:
  gateway_id: esphome:aabbccddeeff
  bus: rs485
  pause_pollers: [0]

Lab C：實體範圍掃描

action: woow_esphome_modbus_scanner.start_scan
data:
  provider: esphome
  gateway_id: esphome:aabbccddeeff
  bus: rs485
  device_profile_id: generic
  start_id: 1
  end_id: 64
  probe_type: holding_register
  register_address: 0
  register_count: 1
  timeout_ms: 500
  safety_confirmed: true
  large_range_confirmed: true   # 64 個站號超過 32，需要第二次確認

          response_variable: snapshot
      until:
        - condition: template
          value_template: "{{ snapshot.status != 'running' }}"
  - action: woow_esphome_modbus_scanner.get_scan_results
    data:
      scan_id: "{{ started.scan_id }}"
    response_variable: result
  - action: persistent_notification.create
    data:
      title: Modbus 掃描完成
      message: >-
        狀態 {{ result.status }}；Responder {{ result.responders | count }}；逾時 {{ result.outcome_counts.timeout }}
請勿 busy loop：每次重查狀態之間要有延遲；側邊欄本身也是每秒一次且不重疊。

10. 回傳資料解讀

Scan status 主要欄位
欄位意義
scan_idcanonical 小寫連字號 UUID，當作不透明識別碼。
provider / gateway_id / bus這次 Scan 的對象。
device_profile使用的 Device Profile（id、名稱、版本）。
status / phase / operation_phaserunning、completed、cancelled、failed，以及目前的操作階段。
completed_addresses / total_addresses / progress_percent進度；取消或失敗時可小於總數。
outcome_counts六種 outcome 的次數，即使為 0 也有 key。
estimated_worst_case_ms / execution_budget_ms保守估算與執行預算，不是 ETA。
lease_status 等見第 8 節。
recovery_status / cleanup_status結束後恢復與清理的證據，與掃描結果分開。
error / error_info失敗原因；請用 error_info 中的代碼做程式判斷，不要解析文字。
六種 outcome 的判讀
outcome是否 Responder解讀
responded是有效回覆，附原始暫存器值。
modbus_exception是CRC 有效的協定例外，附 exception_code。
possible_collision是（模糊）可能重複站號或雜訊，不得當成唯一設備。
identified是只出現在舊版的歷史紀錄；0.5.0 不執行 device identification（FC43/14）。
timeout否只計數，不保留明細，不證明位址空閒。
gateway_error否傳輸無法繼續，Scan 為 failed。

每筆 Responder 有 address、outcome、latency_ms、detail；暫存器讀取另有 register_address、raw_value 或 raw_values（恰好 count 個 0–65535 整數）、attempts，profile 有定義欄位時再加 decoded。結果固定帶 best_effort: true 與 uniqueness_guaranteed: false。

11. 模擬 provider 與 Mock Scenario

provider: mock 不需硬體、不開任何連線，提供 mock:rs485-gateway（Bus rs485）。mock_scenario 選擇一組固定、可重現的結果；FC03／FC04 讀取會回傳原始值。舊欄位 mock_profile 仍接受但已棄用，與 mock_scenario 同時傳會被拒絕。

六種 Mock Scenario
mock_scenario結果
found_default站號 1、3、12 responded，5 為 exception code 2，其他 timeout。
all_offline全部 timeout；不代表真實 Bus 是空的。
partial_timeout2、7、11、21、42 responded，其他 timeout。
modbus_exception4、17 為 code 2，9 為 code 3，其他 timeout。
possible_collision站號 7 為 possible_collision，其他 timeout。
gateway_disconnect到 max(start_id + 3, 4) 起的第一個位址時 gateway_error，Scan failed。
模擬結果絕不可當成現場設備資料；結果表與歷史都會標明 provider。

12. REST API 範例與 token 安全

Home Assistant REST 服務端點為 POST /api/services/<domain>/<service>?return_response；動作資料通常在回應的 service_response。

export HA_URL='https://homeassistant.example'
read -rsp 'Home Assistant token: ' HA_TOKEN; printf '\n'

curl --fail-with-body -sS -H "Authorization: Bearer ${HA_TOKEN}" -H 'Content-Type: application/json' \
  -X POST "${HA_URL}/api/services/woow_esphome_modbus_scanner/start_scan?return_response" \
  --data '{"provider":"mock","gateway_id":"mock:rs485-gateway","start_id":1,"end_id":12,"mock_scenario":"found_default","safety_confirmed":true}'

取出回傳的 scan_id 後：

SCAN_ID='以回傳 UUID 取代'
curl --fail-with-body -sS -H "Authorization: Bearer ${HA_TOKEN}" -H 'Content-Type: application/json' \
  -X POST "${HA_URL}/api/services/woow_esphome_modbus_scanner/get_scan_status?return_response" \
  --data "{\"scan_id\":\"${SCAN_ID}\"}"
Token 是完整帳戶憑證。只用 HTTPS；不要放進 HTML、YAML repo、shell history、URL、截圖或日誌。用完 unset HA_TOKEN，洩漏時立即撤銷。由於任何啟用中的使用者都能操作掃描，任何使用者的 token 外洩都等於讓對方能在你的 Bus 上產生流量。

13. 疑難排解與遷移

常見症狀、原因與處理
症狀可能原因處理
requires at least ESPHome version 2026.9.0ESPHome 太舊升級到 2026.9.0 以上再編譯。
A node supports only one modbus_scanner; scan a second RS-485 line with another node同一節點設了兩個 modbus_scanner 項目一台 Gateway 一條 Bus：只保留一個項目；第二條 RS-485 請用另一台節點。
登錄時「缺少掃描元件」節點沒有 modbus_scanner 或尚未重刷依第 4 節加入元件並重刷。
登錄時 Bridge Protocol 不符／身分不符韌體版本不同或 MAC 與預期不同確認節點與韌體；重新從 ESPHome 裝置登錄。
未知 Bus給的 bus 不是 Gateway 那條 Bus 的名稱省略 bus，或以 check_gateway 取得 Bus 名稱。
Gateway 回報超過一條 Bus節點上有兩個 modbus_scanner 項目的舊版韌體只保留一個項目並重刷；第二條 RS-485 請用另一台節點。
Gateway busy該 Gateway 已有 Scan等它結束或取消。
requires large_range_confirmed=true範圍超過 32 個站號確認時間與流量後加上 large_range_confirmed: true。
違反 Device Profile 限制暫存器不在允許清單、功能碼或數量超出換用合適的 profile 或 Generic。
lease_status 為 unconfirmed連線中斷或釋放未回應Gateway 會在 5 秒閒置後自行恢復；之後檢查設備實體是否更新。
掃描後實體值一陣子沒更新恢復後的第一次輪詢尚未到最多等一個 update_interval。
Repairs 出現 Bridge Protocol v1 警告Gateway 仍執行舊韌體見下方遷移步驟。

從 Bridge Protocol v1 遷移

0.5.0 之前登錄、仍執行廠牌專用 Bridge Protocol v1 的 Gateway 可繼續使用，但維持凍結限制（站號 1–32、FC03、數量 1、允許清單內的暫存器、700 ms、必須暫停、不支援 bus），且每個都會出現 Repairs 警告。遷移：在節點 YAML 加入 modbus_scanner 並重刷 → 整合的重新設定 → 「從 ESPHome 裝置新增或更新 Gateway」選該節點（或手動並選 Bridge Protocol v2）→ 需要時匯入範例 Device Profile。以 Bridge Protocol v2 登錄後 Repairs 自動消失。legacy 支援將在未來版本移除。

測試與維護

專案以 ruff check .、pytest --cov=custom_components/woow_esphome_modbus_scanner --cov-fail-under=90、韌體核心主機測試、前端 Node 與 Playwright 檢查，以及本頁的 tests/tutorial/test_generic_tutorial.py 與 tests/tutorial/browser_check.mjs 驗證。CI 另以 ESPHome 2026.9.0 驗證並編譯兩個韌體範例。文件中的動作、欄位與限制應直接對照 services.yaml、services.py 與 contract.json。

14. 詞彙

Gateway
已登錄、在剛好一條 Bus 上執行掃描元件的 ESPHome 節點。
Bus
Gateway 服務的那一條 Modbus RTU 線，含其序列參數；每台 Gateway 一次一個 Scan。
Enrollment（登錄）
驗證身分與 Bridge Protocol 後，把 Gateway 加入整合；只有已登錄的 Gateway 能被掃描。
Probe
對一個站號的一次唯讀請求。
Scan
在一條 Bus 上對一段站號依序進行的 Probe。
Responder
對 Probe 產生可對應回覆的站號；不證明背後恰有一台設備。
Device Profile
一類現場設備可讀的暫存器、預設值與限制。
Generic Device Profile
內建、廠牌中立的 Device Profile，允許任何暫存器、限制讀取數量、沒有允許清單。
Profile Field
Device Profile 中具名的暫存器，可含單位與倍率，用來把原始值顯示為解碼值。
Pausable Poller
與掃描元件輪詢同一條 Bus、Scan 可暫停的元件；由使用者選擇（以 Bus 為 key 儲存）。
Scan Lease
Gateway 為一次 Scan 暫停選定 Pausable Poller 的期間，由完成、閒置到期或 Gateway 自行強制的上限結束。
Large Range
超過 32 個站號的 Scan，需第二次明確確認。
Legacy Gateway
仍執行 Bridge Protocol v1 的 Gateway，在重刷前維持固定的廠牌限制。
Mock Scenario
模擬 provider 產生的一組固定、可重現結果。
